Bug report file format ​

Report a bug saves a report as one .piwibug file with Download .piwibug, and a failed execution's Export writes one from the test run. Piwi Picker's Replay plays it, and the desktop app imports it into a project as a bug report.

The archive ​

A .piwibug file is a zip archive, its entries stored without compression:

EntryWhat it holds
mimetypeapplication/vnd.piwi.bug-report+zip, always the first entry
steps.jsonThe steps, as a steps file, with the viewport sizes they were recorded at
<title>.spec.tsThe failing test, named after the report's title, such as coupon-not-applied.spec.ts
bug-report.mdThe report as Markdown, in the language Piwi Picker shows
evidence.jsonThe evidence and the context; see below
screenshots/<n>-<moment>.pngUp to three screenshots: marked (a step marked as wrong), finish (a report made from a test run holds its failure screenshot as screenshots/1-finish.png) or manual
steps/<nnn>.jpgThe page as step <nnn> began (steps/001.jpg for the first), as wide as the viewport in CSS pixels, 1,280 at most; up to 100

The mimetype entry is stored first and uncompressed, as EPUB and OpenDocument files do, so its text sits at a fixed place at the start of the file. Piwi reads a file by that content, never by its name: renamed to .zip, to look inside or to attach it where only known file types are accepted (a GitHub issue), it opens the same way. A zip holding steps.json and evidence.json without the mimetype entry is read too.

evidence.json ​

json
{
  "v": 1,
  "context": {
    "origin": "https://staging.acme.test",
    "pageKey": "/checkout",
    "path": "/checkout",
    "browser": "Chrome 141",
    "userAgent": "Mozilla/5.0 …",
    "viewport": { "width": 1280, "height": 720 },
    "time": 1790467200000,
    "extensionVersion": "0.43.0"
  },
  "evidence": {
    "console": [{ "level": "error", "source": "console", "message": "Coupon failed: 500", "page": "/cart", "time": 1790467201000 }],
    "consoleDropped": 0,
    "requests": [{ "method": "POST", "url": "/api/cart/coupon?code=<redacted>", "status": 500, "page": "/cart", "time": 1790467201000 }],
    "requestsDropped": 0,
    "screenshots": [{ "file": "screenshots/1-marked.png", "step": 3, "moment": "marked", "takenAt": 1790467202000 }],
    "screenshotNote": null,
    "outline": "- heading \"Your cart\" [level=1]\n- textbox \"Coupon\": SPRING10"
  }
}
FieldMeaning
contextThe page the report was finished on, the browser, the window's viewport then, the time and the extension's version
consoleConsole errors and warnings, uncaught errors and unhandled rejections, at most 100; consoleDropped counts the rest
requestsRequests that failed or answered 400 or more: method, path with query values removed, status; at most 100
screenshotsEach screenshot's file, the step it was taken after (0-based) and when
stepShotsOptional: for each step with a screenshot, its step (0-based), its file, the box of the step's element on it (x, y, width, height in CSS pixels from the top left corner, or null) and the viewport it shows
screenshotNoteWhy there is no screenshot, when there is none
outlineAn outline of the page in the YAML form of an ARIA snapshot, built by Piwi Picker, at most 400 lines

A report made from a test run ​

A report exported from a failed execution adds an export block beside context and evidence:

json
"export": {
  "source": "execution",
  "executionId": 4512,
  "testTitle": "coupon applies to the total",
  "failedStep": 6,
  "notes": [
    { "title": "POST /api/seed", "location": "tests/cart.spec.ts:8", "reason": "An API request the test sends itself; Replay sends none." }
  ],
  "notesDropped": 0
}
FieldMeaning
executionIdThe execution on the instance the report was made from
testTitleThe test's title
failedStepThe step the test failed at, 0-based, or null when it failed outside the steps (a teardown hook)
notesThe calls of the test the steps leave out, with where they are and why; at most 100, notesDropped counts the rest

The steps hold what Replay can play: the test's actions and its checks of a state, its failing assertion with the expected and actual values of its error, and manual steps for the rest. A step's pageUrl is empty once an action may have left the page, since the run does not record where it went.

Everything in evidence.json is checked when a file is read: a list past its limit is cut, an entry that does not fit its shape is dropped (an export block whose source is not execution is dropped whole, and a failedStep that names no step is read as null), and a screenshot is kept only when its name is one the table above allows; a step screenshot, only when it is named after its step. The steps are checked as a steps file is, and a file whose steps fail that check is refused.
