Core concepts ​

Piwi reuses Playwright's vocabulary where it can, but a dashboard that keeps history needs a few distinctions Playwright doesn't have to make, most importantly between a test and one run of that test. This page names the dozen words a first run meets; the Glossary defines every word the docs and the dashboard use, each under the anchor other pages link.

The object model ​

Read it in two directions:

  • Down: "what happened in this run?" A run holds executions; each execution points at the test it is an attempt of.
  • Across: "how has this test behaved?" A test case holds every execution of itself, in every run, over time. That's the axis flakiness, pass rate and duration trends are computed on.

The words a first run meets ​

  • Project: one suite's results, created the first time results arrive under a new projectName.
  • Test run: everything one npx playwright test invocation produced; one CI pipeline's shards make one run.
  • Test case: a test's identity across time (file, describe path and title), the same on every browser. "This test is flaky" is about a test case.
  • Execution: one attempt of one test case, in one run, on one browser. A retry is an execution of its own.
  • Pass rate and flaky rate: the share of a test's results that passed, and that passed only on a retry.
  • Baseline: the earlier run a run is compared with to answer "what changed?", by default the last passing one.
  • New regression, newly flaky: what a test did differently from the baseline.
  • Environment: a free-text label on a run (staging, production) that analysis can be narrowed to.
  • Failure cluster: the failed executions that share an error fingerprint, triaged once.
  • Cluster state: where a cluster stands, in one sentence (still failing, stopped failing, regressed).
  • Flakiness score: how flaky a test is over its history, which ranks the flaky tests.
  • Tags & ownership: the tags and the owner a test declares, which filter the views and route its failures.
