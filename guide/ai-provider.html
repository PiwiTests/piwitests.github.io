AI provider ​

This page sets up the model Piwi calls: the provider, its model roles, the response language and the context limits. Piwi works without one. Connected, it powers AI diagnosis (the explanation of a failure cluster or a single execution, and the cluster titles), semantic merging of failure clusters, the authoring of AI steps, the AI narrative of quality reports and the assistant; an embedding model also sharpens the Fixed before matches of fix plans, which are found without one. All use the same provider, configured once on the server; API keys never leave it.

Enabling AI diagnosis ​

Configure a provider via Settings → AI, or with environment variables. PIWI_AI_PROVIDER is the switch: once it is set, the provider configuration comes from the environment and the UI shows its provider, key and base URL read-only. A model or temperature picked in the UI still overrides the env one, and a role the environment leaves out can be turned on in the UI by reusing a role it sets. Without PIWI_AI_PROVIDER, the other provider variables below are not read.

VariableDescription
PIWI_AI_PROVIDERanthropic, openai, claude-cli, codex-cli, or deepseek-cli
PIWI_AI_API_KEYProvider API key (stored encrypted when set via the UI; never returned by the API)
PIWI_AI_MODELModel name (default: claude-opus-4-8 for Anthropic)
PIWI_AI_BASE_URLBase URL of the provider API: required for openai, OpenAI itself (https://api.openai.com/v1) included; optional for anthropic (a gateway or proxy)
PIWI_AI_AUTO_DIAGNOSEtrue to diagnose, when a run finishes, the clusters that failed in it and have no completed diagnosis yet
PIWI_AI_AUTO_DIAGNOSE_MAXMax clusters auto-diagnosed per finished run (budget cap; default 3)
PIWI_AI_RESEARCH_MODEL / _PROVIDER / _BASE_URL / _API_KEYOptional research model for two-stage diagnosis; provider/base URL/key default to the main ones
PIWI_AI_EMBEDDING_PROVIDER / _MODEL / _BASE_URL / _API_KEYOptional embedding model for semantic failure clustering (OpenAI-compatible only: Anthropic has no embeddings API)

Saved keys are bound to their provider and base URL. Enter the key again when changing either.

The Configuration reference lists every AI variable.

With PIWI_AI_AUTO_DIAGNOSE on, the PIWI_AI_AUTO_DIAGNOSE_MAX budget goes to the clusters that need a model most: the order is on Diagnosing automatically.

Streaming diagnosis ​

A diagnosis streams into a live panel, stage by stage (Watching it stream). To be told when a diagnosis finishes without watching the panel, turn on Settings → AI → Diagnosis notifications: a per-browser preference that shows a browser notification on completion once you grant the permission.

Local Codex CLI ​

Use Codex CLI with a ChatGPT login, or official DeepSeek Harness with DeepSeek credentials.

Model roles ​

Piwi calls models in up to four roles:

  • Diagnosis: the main model that writes the final diagnosis (required to enable AI). The quality report narrative uses it too.
  • Research: an optional cheaper, faster model that pre-analyzes the failure first (two-stage diagnosis).
  • Embedding: an optional embeddings model that powers semantic failure clustering and the Fixed before similarity.
  • Assistant: an optional model the assistant answers with; unset, it uses the diagnosis model.

In Settings → AI, the Provider card sets the diagnosis role and the Features card turns on the others. Each reuses the diagnosis provider and key with a model of its own, or runs on another provider.

Providers ​

Anthropic (recommended)

bash
PIWI_AI_PROVIDER=anthropic
PIWI_AI_API_KEY=sk-ant-...
PIWI_AI_MODEL=claude-opus-4-8

OpenAI

bash
PIWI_AI_PROVIDER=openai
PIWI_AI_API_KEY=sk-...
PIWI_AI_BASE_URL=https://api.openai.com/v1
PIWI_AI_MODEL=gpt-4o

OpenAI-compatible or local (Ollama, LM Studio, vLLM): set the provider to openai and point the base URL at the local endpoint:

bash
PIWI_AI_PROVIDER=openai
PIWI_AI_BASE_URL=http://localhost:11434/v1
PIWI_AI_MODEL=llama3.1
PIWI_AI_API_KEY=ollama   # optional: sent only when set, for servers that check one

A local model keeps every diagnosis on your own infrastructure; see Privacy & data flow.

Claude Code CLI (local): pick Claude Code under Command-line tools in the desktop app, or on a server with PIWI_CLAUDE_CLI_PATH set. It runs the local claude CLI, unmodified, on the sign-in Claude Code already has: Piwi stores no key and never signs it in; Settings → AI shows the sign-in and a live usage tally. Under Anthropic's terms, a Claude subscription (claude auth login) runs only in the desktop app, for its one subscriber; a server needs an API key (ANTHROPIC_API_KEY, apiKeyHelper), a gateway token (ANTHROPIC_AUTH_TOKEN) or a cloud provider (Bedrock, Vertex AI, Foundry). Every role but embeddings can use it. Each call runs for one turn with every tool and MCP server off and none of the server's own environment variables, so an error message in a prompt cannot make the CLI run a command; a Claude Code too old to turn its tools off is refused. The CLI reads the prompt as text, so a diagnosis it writes gets no screenshot. The assistant is the exception: one CLI run writes a whole answer, with one MCP server attached, this server's endpoint for that answer. It serves the assistant's tools only (the read tools, run with your access, and the blocks of an answer; in the desktop app also read_local_source, held to the folders linked to your projects), on a token minted for that answer that stops working when it ends; the desktop app's own token never reaches the CLI. The CLI's built-in tools stay off. An older Claude Code answers step by step instead.

In Settings → AI, the Ollama and LM Studio tiles fill in their local address and OpenAI-compatible takes any other server. Test connection keeps the answer, or the provider's error, in view, and one Save stores every section you changed. AI actions show once a provider is configured.

Response language ​

Set a response language and every free-text field a person reads (summary, root cause, evidence, fix description and AI-generated cluster titles) comes back in that language, while code, locators, paths and error text stay verbatim. Set it instance-wide in Settings → AI (or PIWI_AI_LANGUAGE, e.g. French, which locks the field), and override it per project under Project → Settings → AI diagnosis. This is what makes a French ticket's Most likely section French: the ticket's copy follows the destination's language and the prose follows this setting. Unset, responses are in English.

Context limits (and token cost) ​

Every piece of evidence sent to the model costs tokens. Piwi caps each input so diagnoses stay fast and affordable. Override the caps in Settings → AI → What the model receives or via env (env wins; the UI then shows the field read-only).

The full list of PIWI_AI_MAX_* limit variables, their defaults and their clamping ranges lives in the Configuration reference → AI context limits, generated from the same registry the server reads. The diagnosis context preview (Context sent to AI) shows what was trimmed to fit before you spend tokens.

Screenshots are the one input a provider can refuse outright: many self-hosted and gateway models are text-only and reject a request that carries images. Piwi retries that call without them, so the diagnosis still runs on the text evidence. Setting PIWI_AI_MAX_IMAGES=0 skips the rejected first attempt.

Usage and quality ​

AI usage in Settings → AI counts, per provider and model over 7, 30 or 90 days, the diagnoses, the failed ones, the assistant's answers, the tokens and the average duration. Its second table, how each model's diagnoses fared, is explained on How diagnoses fare.
