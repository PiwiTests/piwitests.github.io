End the test ​

NeedsCapture fixtures

At a stop, End the test ends the test there, as if it had called test.skip() at that line: the locator call it stopped before never runs (Playwright 1.62 or later), nor the rest of the test, and Playwright reports it as skipped, its skip annotation reading Ended from Piwi. Its result reads Ended at a stop, never a plain skip, on the run's page, the test's pages, Piwi Picker's Runs window, the desktop app's Local runs tray and both editors. The run goes on with its next test. Use it once you have seen what you stopped for, or recorded the steps you were missing, and the rest of the test has nothing to show you.

Where it is ​

It is offered at any stop but a failure, with a reporter newer than 0.62.0:

  • VS Code: End test in the stopped line's hover, the status bar beside Finish, and Piwi: End the test in the palette. It has no key: bind one in Preferences: Open Keyboard Shortcuts (search piwi).
  • A JetBrains IDE: End test in the stopped line's inlay and the arrow's menu, Tools → Piwi → End the test and the status bar item's menu. Give it a key in Settings → Keymap.
  • The pause bar: End the test.
  • Piwi Picker's Runs window and the desktop app's Local runs tray: End the test, beside Finish.
  • An agent: run_control with end, answered as the test ends.

While a Pause waits for a call ​

Pause stops a test before its next call, so a test inside a long one (a click that waits for a button, a waitForTimeout) stops only once it returns. Meanwhile, with a reporter newer than 0.67.0, the Runs window and the desktop app's tray say the call it waits in and, for a locator call, how long it has run, and offer End the test there. The Piwi item reads Piwi: pausing… · waits in the call and how long it has waited, in both editors, and End the test in its menu (Tools → Piwi → End the test in a JetBrains IDE) ends it:

  • A locator call or an assertion, with Playwright 1.62 or later, is given up at once, and the test is skipped.
  • Another call (a waitForTimeout, a navigation) finishes first, and the test is skipped at its next locator call, or as its function ends.

What runs, and what does not ​

  • At a locator call or an assertion (click, fill, expect(locator).toBeVisible()), the call is given up before it runs, with Playwright 1.62 or later; an older one runs it first, and the editor says so. At a page.pause(), nothing after it runs.
  • At another call (a navigation, a key press on the page, page.evaluate), the call runs first: Piwi does not hold it. The test is skipped at its next locator call, or as its function ends, and the editor says so.
  • At a failure, it is not offered: Resume lets the test end as it failed, and the failure is kept.
  • In a beforeEach hook, it skips the test. In an afterEach hook or a fixture's teardown, the test's function already ended: it goes on as Resume does, keeping the test's result, and says so. Piwi never stops in a beforeAll or afterAll hook.
  • After it, the test's afterEach hooks and its fixtures' teardown run as after any skip, so its page closes as usual, with nothing of Piwi left in it.
  • A retry is an attempt of its own. Playwright does not retry a skipped test; a failure you let end runs the next attempt, which stops at your breakpoints as the first did.

How the result reads ​

The test keeps Playwright's status, skipped: it counts among the skipped tests, and its run passes or fails on its other tests. What changes is the mark each tool puts on it:

  • The dashboard: the test's row on the run page, its execution's status chip and its line in the test's recent executions read Ended at a stop instead of Skipped, and the run page's header marks the run beside its status (Ended at a stop, or 3 ended at a stop for more than one). Copy run summary names them among the skipped: 4 skipped (1 ended at a stop).
  • Piwi Picker's Runs window: the run's progress line counts them, 9 of 9 tests · 1 ended at a stop, in the window's language; the desktop app's Local runs tray reads Passed · 1 ended at a stop once the run ended.
  • The editors: the status bar's run progress counts them (1 ended at a stop), and the notification of a run the editor started names them beside the skipped, 3 passed, 0 failed, 1 skipped (1 ended at a stop).

The count reaches the editors, Piwi Picker and the desktop app from a reporter newer than 0.68.0; with an older one they count the test as skipped. The dashboard reads the skip annotation, so it marks results already stored too.

Limits ​

  • Playwright's calls alone. The test's own code between two calls, a loop or a helper, runs until its next call.
  • One test. It ends the stopped worker's test; the run's other tests run. To end the run, Stop it (one Piwi started, from the editor, the desktop app or the Runs window) or end it in its terminal.
