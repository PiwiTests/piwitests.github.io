Watch a run ​

NeedsReporter

A run that reports to a Piwi instance has one number there, #78, and one page. Every tool that shows the run while it goes names it by that number, links that page, and says how far the run is and where a test stopped in the same words, so a run started in VS Code reads the same in the terminal, in Piwi Picker's Runs window and on the dashboard.

The run's number and page ​

The reporter learns the run's number as the run starts: from the global setup that registered it, else as its stream to the instance opens. It prints the page once, and tells it to the editor or the desktop app that follows the run. The page is under the instance's public address when the instance sets PIWI_SITE_URL, else under the address the reporter reached it at. A tool links it only on this machine or under an instance it connects to itself: in an editor, the instance of a Playwright config of the window; in the desktop app, the team instance whose run requests it takes. A page elsewhere, which the test's own code could name, is not shown, and the run reads as one with no number.

WhereWhat it shows
The terminal[Piwi Dashboard] View live progress: https://piwi.example.com/test-runs/78, once, as the run starts
VS CodeThe run-control item: #78 · 3 of 9, its tooltip Open run #78; the status bar item, while your run goes: Open run #78 (running) first in its tooltip; Piwi: Open the run page and Piwi: Open the run in progress in the Command Palette
JetBrains IDEsThe status bar item: Piwi: run #78 · 3 of 9, kept beside a stop or a share; Open Run #78 in its menu; Open Run #78 (Running) in place of Open the Latest Run in the Dashboard while it goes
Piwi Picker's Runs windowRun #78, Open and Copy link on the run's card, while it runs and after it ended, with its progress and how it ended
The desktop app's Local runs trayRun #78 · Open under each run of its hub, a run a team instance asked for included, whose page opens in the browser; Open run #78 on a run the app's own server holds
Debug in my editorOnce the editor runs the test: "Following run #81 in VS Code · Open" beside the button

A run that reports to no instance, or that runs with streaming: false and no global setup, has no number until its results are sent, and the tools show it without one.

How far it is ​

The reporter's own process tells the editor or the desktop app how many tests the run holds, how many ended and how, and how the run ended with its first failure. The editors' status bars and the Runs window count it the same way: each test once, by its last attempt. The desktop tray counts the lines of the run's output instead, a retry again.

On the dashboard, Home's Recent activity, a project's runs list and the Projects page show a running run with the count bar and how many results are in: 120 of 400 · 2 failed. Its row moves on by itself as results reach the instance, at most every 2 seconds, without the page reading the list again. Until the run ends these count each result as the reporter sends it, a retry again; the run's page counts each test once.

The status bar item's tooltip also says what each worker runs now (Worker 2 · cart › adds a mug · stopped). In VS Code, the Testing view's test run of your run writes in its output each test a worker starts, each stop and why, with the line it stands at, and each stop answered.

In VS Code, a run in progress that is not yours, a CI run or a teammate's on your branch or on the branch your results are compared with, names itself so: the status bar says CI run #125 or run #126, and the Testing view shows it as Piwi: CI run #125 on main, its tests' results as they end, never as your tests running. Your own run stays in the status bar whichever Playwright config the active file belongs to.

Where a test stopped ​

A test of a run on your machine stops at a breakpoint, after a step, at a Pause, at the line it was run to, or at page.pause(). Every tool says why in the same words:

  • Stopped at a breakpoint
  • Stopped after a step
  • Paused
  • Stopped at the line it ran to
  • Stopped at page.pause()
  • Stopped, for a reason a newer reporter names

A stop an agent asked for reads Paused by the agent in the editors. A failure held for a look says how the test failed instead. The run page shows the stop on the test's row (stops, shared or not), the editors above the stopped line, the Runs window on the worker, and the terminal on a line of its own:

text
[piwi] Stopped at a breakpoint at tests/cart.spec.ts:12 before Click: Resume, Step or Finish in Visual Studio Code.

The line names the editor that steers the run, or the desktop app. After you edit the file at a stop, the Runs window names the stopped line where it stands now, as the editor does.

At a stop of a headed run, every tool offers Show the browser, which brings the test's window to the front, as far as your system lets a window come forward: Piwi: Show the stopped test's browser in VS Code and the stop's hover, Tools → Piwi → Show the Stopped Test's Browser in a JetBrains IDE, and a button in the Runs window and the desktop app's tray. A headless run has no window to show, and an older reporter offers none: update it.

The terminal's lines ​

A run prints one line for its page, and one when it follows an editor or the desktop app (runs started outside Piwi). A run whose output goes to a file or a pipe follows it unattended and says so:

text
[Piwi Dashboard] Following this run in Visual Studio Code (pid 41230), unattended: its output goes to no terminal, so no failure waits and only a Pause stops it. PIWI_EDITOR=on attends it, PIWI_EDITOR=off runs it alone.

The other lines of a run's start (its project and Playwright version, its shard, the stream opening on time) are printed with PIWI_VERBOSE=true alone. A stream that opens late, a failure link and a warning are always printed.

In a terminal outside CI, the run's page is a link. Windows Terminal and ConEmu show how far the run is in the tab and the taskbar, and Ghostty 1.2 or later atop the terminal, red once a test failed. PIWI_TERMINAL_PROGRESS=off turns both off, and PIWI_TERMINAL_PROGRESS=on sends the progress to any terminal: one that reads it as a notification shows one at each step.

When the run does not reach the instance ​

When a run the editor started ends without reaching the instance, the editor says which of two things happened: its reporter ran but sent nothing (its lines in the run's output say why: the server address, the key, or an instance that refused it), or the Playwright config has no Piwi reporter.
