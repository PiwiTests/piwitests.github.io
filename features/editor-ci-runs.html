CI runs in your editor ​

NeedsEditor extension

While CI runs your branch, the editor extensions show that run beside your own: its progress, its tests as they end, the line each running test is at, and, when its project has the live view on, its pages. It is watched only, but for the controls offered to the people who may control the run: Let it go on a test the project holds at its failure, and Pause, Resume and End the test when the project lets them pause a CI test. Nothing else steps, holds or shares a CI run from the editor.

Which runs ​

A CI run of the branch your workspace reads or has checked out, or a teammate's on it or on the branch your results are compared with, shows while it runs. The editor finds it as the instance announces it, or as it reads the latest run of the branch in progress. It follows the two newest runs of a branch at most, and stops following a run as it ends, as a newer run takes its place, or when the workspace reads another instance, project or branch.

VS Code's status bar says CI run #125 or run #126, and its Testing view Piwi: CI run #125 on main, with results as they end; your own run keeps the status bar. A test line Piwi marks keeps its own latest result, and its hover names the CI run running it.

The CI run's tests ​

  • The CI Runs view of VS Code's Piwi panel, and the CI run tab of the JetBrains Piwi tool window, show while a CI run runs. Each lists CI run #78, its branch and progress, Open run #78 and its tests: those running, then the latest that ended, failures first. A running test opens the call it is at, else its spec (a double click in JetBrains).
  • The line each running test is at ends with a plain mark in the CodeLens or inlay color, CI run #78 · worker 2: Click getByRole('button'): a CI position, never a stop, on the line of the run's commit. It shows in a file of your workspace only, placed from the run's own steps: never one in node_modules or outside the workspace.
  • Piwi Picker's Runs window lists them too: CI runs.

Watch a CI lane ​

Watch, under a running test whose project has the live view on, opens its lane read-only, named CI run #78 · worker 2, in the VS Code worker panel, the JetBrains Worker tab or the Runs window: no Interact, no pick. It follows the lane through its next tests, and ends with the run, as you hide or close the view, or as the instance closes it, saying why. Its images come from the team instance, read with the editor's connection; under the image, the same layers as a local lane (Beside the image).

Watch on the dashboard opens the lane on the run's page, offered where the editor cannot show it (an older instance, a refused Watch).

A failure held for you ​

When the project holds a failing CI test for its controllers and your editor's connection may control the project's runs (its key is a Maintainer's or a Project admin's), your watch of a lane counts: a test that fails in it waits at its failure, as it would for the run page. The worker panel or the Worker tab then says Failed, held at its line · Held for Ana · until 12:05, the error, its place (which opens the failing line), and that the CI job's own timeout still runs; the CI Runs list marks the test Failed, held at its line. Let it go ends the wait, once: the test tears down as it would have, its result unchanged.

Let it go goes on your watch of that lane, so it shows only while you watch it, and only once the instance has said your connection may control the run. The Runs window does the same with its own connection (Where it shows). Anyone else watching sees the hold without it. A refusal is said in the instance's words, under the caption.

A test paused for you ​

When the project also lets its controllers pause a CI test, the same watch offers Pause while the lane's test runs. Until the test stops before its next call, the panel or tab says Pause asked by Ana, and Resume takes the Pause back; one the worker dropped says why. Paused, it says Paused by Ana · until 12:05, the call it stopped before and its place, and the job's timeout note, with Resume and End the test; the CI Runs list marks it Paused. Each button is asked once in each state of the lane, its refusal in the instance's words.

Limits ​

  • Watched only, but Pause, Resume, End the test and Let it go, for those who may control it. No other control, share or hold reaches a CI run, and its position is never a stop.
  • One worker per editor. The worker panel or tab watches one lane, a local worker's or a CI run's: watching another moves it there.
  • A run's steps. The positions come from the steps the CI run's reporter streams, so a run whose reporter streams none lists its tests without them.
