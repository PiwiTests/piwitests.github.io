Live view of a run ​

NeedsReporterCapture fixtures

In a project that turns the live view on, a running test of a CI run, or of a run a developer shares from their machine, gets Watch on its run page on the team instance: the page that worker is on, a few images a second, each with the call it was taken at, for a CI run that seems stuck or a teammate's paused test. Nothing you do in the view reaches the test.

Where to watch a run ​

A CI run, or a shared run, is watched here. A run you start yourself shows in its browser when headed, and in your editor, Piwi Picker's Runs window and the desktop app's tray, running or stopped: Watch a local test. A run that reports to the desktop app gets no live view key, so no team Watch.

Turn it on ​

The live view is off in every project. A Project admin turns it on in Project → Settings → Live view, or from a running run's status. It applies to each CI run that starts after, as the reporter's global setup registers it: wrapConfig adds that setup. A CI job is told by its provider's variable (GITHUB_ACTIONS, GITLAB_CI, …) or by CI set to anything but false or 0. Such a run's log then says:

txt
[Piwi Dashboard] Live view on for the specs that use Piwi's fixtures: people who may open this run can watch their tests' pages on the dashboard while it runs. Nothing is stored.

A spec file that imports test from @playwright/test instead of your capture fixtures has no view: the log names the first one. A CI run without a view logs why instead, for a reason Check availability lists, with the error the instance answered.

Turning it off ends every view at once. Turned on again, a run that had a view and still runs gets it back within a minute.

A CI run's workers keep their view through an outage or a restart of the dashboard: each tries again after 1, 2, 4, 8 and 16 seconds, then every 30 to 60 seconds while the run lasts. A worker whose view stays out says so once in the run's log, with the cause, and once more as it is back.

Check availability ​

A running run's Tests tab says Live view available, or what is missing, its help giving the step:

It saysWhy, and what to do
Live view offA Project admin turns it on for the next runs, from its help.
Live view unavailableThe run has no key: it started before the setting was on, without wrapConfig's global setup, while the instance did not answer that setup, or with streaming off. Start a new run.
Live view waitingNo worker is connected yet: they are starting.
No worker connectedTests run without one: the specs import test from @playwright/test, not the capture fixtures.
Not shared liveThe run is on a developer's machine: they share it.
Watch says nothing has come for 35 secondsA reverse proxy buffers the live view's streams: turn its buffering off (Reverse proxy).

Watch a worker ​

On the run page's Tests tab, Watch at the end of a running test's row opens its worker's view, docked beside the page (a sheet on a smaller screen): the test's page as the browser paints it, under it the call the image was taken at (Click getByRole('button', { name: 'Pay' }) · checkout.spec.ts:30). A still page shows as the view opens, then sends no new image, so the caption names the step the test began since. Widen the panel or open it full screen; a click on the image zooms. Under it, the page's events, text and filmstrip and Inspect; Watch all shows every worker at once.

The view follows that call: how long it has run (while its test stands at a stop, the stop in its row's words, Paused), Playwright's log of it as a failed call's error prints it, and while it waits, what its locator matches (no element yet, several, or one not enabled), outlined on the image, with the point a click acts on; Zoom to the element crops the image around it. In a CI run this needs Playwright 1.64 (1.63 shows the log without the matches, an older one the call alone); a shared run reads it inside the worker, pausing nothing.

A view follows its worker's lane: it says how each test ended, lists the lane's earlier tests and goes on, across worker restarts; untick Follow the worker's next test to end it with its test. The page's address names the lane (?watch=2; ?watch=3.2 for worker 2 of shard 3) for a link. It ends with the run, saying how it went, 30 s after its lane's worker left, as the live view turns off, or as you close it. A view that cannot open says why.

What is sent, to whom, and what is kept ​

  • No image from a run on your machine until you share it. Its workers open no connection; its stops show as text. Shared, its worker sends the team the images of the one view its own tools watch.
  • Nothing while nobody watches. Each worker of a CI or shared run keeps one connection to the dashboard and says only when its test stops and goes on. No image is taken.
  • While someone watches a worker, that worker sends JPEG images of its test's page at quality 50, at the size the view shows them in device pixels, 1280 by 800 at most: four a second to a view, one to a Watch all tile, and about 256 KB a second, a heavier image holding the next one back longer. A test whose trace or video already films the page shares that recording's images, 800 pixels wide at quality 90. The recording stays whole. A test that starts its own page.screencast gets it, and the view goes on with an image a second. A view also gets the call's log. Nothing of the view is a step of the test or an action of its trace.
  • Only to people who may open the run: watching needs what opening the run needs, the project's roles. On an instance with authentication off, that is anyone who can reach it. A CI lane watched in your editor comes from here, read with the editor's key, and counts among the run's watches for the key's owner, as a dashboard tab does; the editor keeps none.
  • Nothing is kept. The dashboard relays each image to the people watching that worker and drops it: never written to the database, the logs or an export. A viewer that reads slowly gets the latest image alone. The run's trace stays the record.

Masked in the worker, with @piwitests/reporter 0.64.0 or later (an older one masks nothing): before an image leaves it, the worker paints over password fields, fields whose autocomplete asks for a one-time code or a card's number or code, and the project's Masked elements (Playwright locators). While one shows, two images a second go at most. A zoomed-in page sends no image. A secret in the page's own text still shows; the caption and the log hide credentials and typed text. The workers reach the dashboard with a key the run got as it registered: it opens this run's live view and nothing else, ends with the run, and is never in the environment of the tests, their hooks or their fixtures. The dashboard keeps the key's SHA-256 digest with the run, never the key, so a dashboard that restarts takes it back from the workers while the run lasts.

Limits ​

  • Watch only. No input and no controls: a test is stepped from the editor or the Runs window.
  • One page at a time: the page fixture's, else the page of the test's latest call (which).
  • Sixteen pages watching a run at a time, four of them one person's with authentication on: a fifth closes that person's oldest. Its workers send 4 MB of images a second at most together.
  • One dashboard server. The view is relayed in the memory of one server, so it needs a deployment of one server (Resource requirements), which sticky sessions do not make up for.
