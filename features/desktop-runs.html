On this page

Desktop app runs ​

NeedsCapture fixturesDesktop app

This page is about each worker of a run the desktop app starts: its stops, its page and the code a stop makes. Every Playwright run the app starts names the app as its hub: a Re-run of tests, a reproduction, a bisect step, a Flake Lab run and a bug report's run. Its Local runs tray shows each worker of the run beside its output, and steers the test as the editor does: Pause and step from the editor. Nothing leaves your machine unless you share a run live. The tray's runs themselves, their progress, Stop, Run again, their output and a reload: Local runs tray.

Each worker ​

While a run goes on, the tray shows each worker's test, project and attempt, and whether it runs. Pause stops the test before its next call that acts on or checks the page. A test also stops at a page.pause(), and a headed one shows Piwi's pause bar there.

At a stop, the tray says why the test stopped, the call about to run (Next) and its place in your code (At), with an image of the page. Resume lets the test go on, Step runs one call and stops before the next, Finish runs it to its end without stopping again, and End the test skips the rest.

A run of several workers shows one at a time, behind a tab each (worker 2), with Pause all and Resume all, as in the Runs window.

Hold failures, a switch on each running run, holds a failing test at its line: Failed at, its error under it, and Resume to let it end as it failed. It is on from the start for Reproduce, which runs to show you the failure, and for a run started with it on; Run again keeps it. The switch turns off as the app's last window closes, unless another tool set it since.

The tray opens at each stop, and tells you of one in the background: stops while you look elsewhere.

Watch ​

Watch, on a running worker in the tray or its test on the run's page, shows its page as the test runs and at each stop, until you turn it off (Watch a local test).

At a stop of a worker nobody watches, Watch shows the stopped page as it paints, in place of its image, and stays on for the worker's next stops until you turn it off. Interact, beside it, plays your input on the page; Tab leaves the view unless a click into it took the keyboard. Nothing keeps the frames.

Pause and watch, on a running test of the run's page in the app (Open run #N on the run in the tray), pauses the test as Pause does and watches its worker: the tray opens at the stop, the page live, and the row says where it stopped, with Show its page to open the tray on it again.

Pick on the image (Playwright 1.60 or later), or a Shift+click on the image or the view, names the element under the pointer: its locator shows under the test, with Copy.

Under a watched page, the tray shows what pixels cannot (beside the image), and Open the trace so far, in its head, opens Playwright's trace viewer on the running test's trace up to now (Open the trace so far).

Inspect, beside it, shows that test's page at each call as on the run page, with the locator picker. The app's server reads the trace file Open the trace so far checks, while the tray shows the lane and the window is not hidden; the window hears each page's call and reads the page rendered, never the file's path. Each page is cleaned as a worker cleans it for the run page, the values any frame's secret fields held hidden in every page, iframes included, and stays in memory until the test ends. As Inspect opens, it reads a page's snapshots since its navigation, 8,192 or 16 MB at most; every lane's pages, with the snapshots read to build them, share 256 MB, past which it keeps no more. A page with a frame it cannot read whole shows again from its next navigation, and the reading stops when the trace folder, a folder above it or its resources folder becomes a link or no longer a folder: Inspect says why each time.

Code to copy ​

The app holds no editor, so the code a stop makes (Assert a region, Mock a request, a picked locator) comes to the tray, to copy: Code from the runs.

Share live ​

A run that reports to your team's Piwi instance can be shared live there for a teammate to watch: who sees what, and why a run cannot be. Stop sharing… asks first, naming what closes there.

For agents ​

The app's MCP server (its MCP server page connects your coding agent) serves these runs with the tools of Run control for agents: an agent follows a run, pauses or steps it, and reads and acts on the stopped page as you can and no further. Its run_start starts a run of the tray, titled with the agent's name (in the desktop app).

The tray shows what it does: a stop it asked for says so (Paused by the agent), as does its first action at a stop. The code code_write makes (the steps it took, an assertion, or a locator for the stopped line) comes under Code from the runs, to copy, and back to the agent in its answer. An agent sees no Flake Lab run, bisect or lab job: nobody attends them.

The tray names who else is there: the tools that have a run open (Also open in Piwi Picker · An agent follows this run), who watches a worker's page, and who drives a stop: Take control from an agent, and Give back.

An agent pauses, steps or runs to a line only while the app's window is open, in the tray included: a headless stop goes on with no window to show it. A stop it asked for goes on two minutes after its last call.

A reproduction in your editor ​

A job the app runs in a throwaway worktree of a commit (Reproduce here, a bisect step, a Flake Lab run) follows the editor window whose workspace holds the project's linked folder, by the rules a terminal run follows, else the app. It follows only an editor extension that knows these reproductions (an older one leaves it to the app), and a bisect step or a Flake Lab run, which nobody attends, only one that knows such runs too.

  • Its stops show in the editor at the failing line of the worktree's file, outside the workspace, marked the desktop app's reproduction at commit abc1234, in a throwaway checkout. A reproduction holds its failures from its start, as in the app.
  • Its code is to copy. Assert, Assert a region and Mock a request offer the code with Copy the code and write nothing: "This reproduction runs at commit abc1234 in a throwaway checkout: copy the code into your own file." Record is refused there, and a pick goes to the app's window, to copy.
  • The app keeps it. Its Local runs tray says where its tests wait (In Visual Studio Code), read only, stops it, and shows its verdict when it ends; the editor offers no Stop.

Limits ​

  • No recording. Record, and a stopped test's Pick and Assert buttons, which act in the test's window, end in an editor: run the test from VS Code or a JetBrains IDE to use them.
  • A linked folder. A reproduction or a bisect step runs in a throwaway worktree, which no project links: its stops make no code here. With an editor open on the linked folder, the job runs on that editor instead, which offers its code to copy (A reproduction in your editor).
  • A file changed since the run started makes no code: run the test again.
  • Run to the cursor stays in the editor, which has the file.
