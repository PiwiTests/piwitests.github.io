Runs window ​

NeedsReporterCapture fixturesBrowser extension

Piwi Picker's Runs window follows the test runs VS Code or a JetBrains IDE starts, from a window of its own beside the test's browser. It pauses, steps and resumes them, writes code from a stop through the editor, and, for a test that runs headless or in a remote container, shows its page live while it runs, takes your clicks and keys on it, and picks a locator on its image. The editor shows the same stops: Pause and step from the editor.

Open it ​

With Piwi Picker paired with VS Code or a JetBrains IDE, or with the desktop app, the popup shows a Runs tile under More tools, muted with Not connected while none of them answers. It opens the Runs window, to keep beside the test's browser, where you left it last. For each run the editor started, it shows the folder and the command, how many of its tests ended (3 of 9 tests · 1 failed), then each worker's test and whether it runs or where it stopped: the file and line, the call about to run, and an image of the page. A run that ended says how: passed, failed with its first failure, timed out or interrupted. The count and the outcome need @piwitests/reporter newer than 0.67.0. While none of its tests is stopped, a run without Watch says how one stops: at a breakpoint, a page.pause() or Pause. A run started outside Piwi shows too, marked Terminal or Test runner.

The controls ​

Pause stops a running test before its next call; while the test waits in a long one, its row says which (a locator call, for how long), with End the test. At a stop, Resume, Step, Finish and End the test do what they do in the editor; Run to cursor stays in the editor. A live run of several workers shows one at a time, behind tabs marked with their state, with Pause all and Resume all under its name. A new stop takes the tab from a worker neither stopped nor watched, and Resume or End the test moves it to the next stopped test. Stop the run ends a run an editor or the desktop app started, not a terminal's or test runner's. Resume, Step and Finish have keys, and the run shortcut resumes or pauses every run from any window.

A failing test is held at its line, a headless one while its run's Hold failures is on: Failed at in red, its error under it. Resume lets it end as it failed; Pick replaces the failing locator. Hold failures, on each run, turns it on or off.

Share live, under the run's name, shares the run with your team: Share a run live.

Each run names who else has it open (Also open in the desktop app, An agent follows this run), and each worker who watches its page (Watched by you and Visual Studio Code). One tool drives a stop at a time: an agent that paused it or acts on it, else the last whose person clicked, typed or picked there. While another tool drives it or an agent follows the run, Take control makes it yours: an agent's actions there are refused until you Give back. A stop an agent asked for reads Paused by the agent: driving a stop.

Code from a stop ​

The actions under Code (the last two in More once five show) send code to the editor, which writes it at the stopped line, when its Piwi extension and your reporter take them. Pick and Record start the pause bar's Pick a locator and Record here, Assert the recorder's Check an element, and Assert a region a pick whose ARIA snapshot becomes toMatchAriaSnapshot. They run in the test's page: where the pause bar shows, or, at a headless stop, once you watch it, driven through the view; until then they show held, saying Watch to use. Mock a request lists the page's fetch and XHR requests, credentials hidden: the one you choose becomes a page.route. Under the test, the window says the code went to the editor, with what to review in it, or why not.

Watch a test ​

Watch, on a worker's row, shows its test's page as it paints, running or stopped, and Pause and watch pauses it too: Watch a running test. The last frame stays, marked Running…, until the next one comes. An older reporter's row says to update it; with one newer than 0.61.0, its stops have Watch live, which watches each stop alone and, left on, the worker's next ones.

The view fills the window's width, at most ten frames a second, with a red Live badge. Only the window that asked gets the frames, and nothing stores them: they go from the test's worker to the editor service and the extension's background worker, on your machine or through the port your IDE forwards from a remote window.

Watching ends when you turn it off, the run ends or you close the window, and pauses while the window is minimized or the connection to the editor is lost.

At a headless stop, nobody sees the test's page. Watched, the picker, the recorder's panel and the check panel appear in the view, and you answer them there as in a headed browser; their code reaches the editor the same way.

Click and type on the view ​

While you watch, Interact, beside Watch live or Watch, sends your input on the view to the page as a person's would, the picker and the recorder included:

  • The pointer: moves, left and right clicks, double and triple clicks as your system counts them, drags, and the wheel once the view has the focus. Ctrl, Alt and ⌘ held with a click are held in the page too.
  • The keys, while the view has the focus (a focus ring around it): characters are typed, named keys (Enter, the arrows, Backspace, Delete, Home, End) pressed, with Shift, and Ctrl (⌘ on macOS) with A, Z, Y, Enter and the editing keys. A paste types the clipboard's text.
  • What stays the window's: the browser's other shortcuts, the function keys, Esc and Tab, as the keyboard shortcuts say.

A hint under the view says so the first time. What you hold down is let go before the test goes on.

Pick on the image ​

Pick on the image, above the image, or a Shift+click on the image or the view, names the element a click under the pointer would reach (a dialog or a banner over the page included), without touching the page: the locator the pause bar's Pick a locator would rank first for it, sent to the editor in place of the stopped line's. The window shows that locator, or why there is none, with Copy when no editor took it. It works on a headed stop's image too. Esc turns it off. It needs Playwright 1.60 or later, and says so on an older one.

The desktop app's runs ​

Paired with the desktop app, the window lists the runs the app starts beside your editor's, marked Desktop app: reproductions, bisect steps and bug reports included, with the same controls and live view. With no editor paired, it follows the app alone. The app holds no editor, so Pick, Record and Assert in the test's window are not offered; the code Assert a region and Mock a request make goes to the app's window, to copy there, and the window here says so: Desktop app runs.

Limits ​

  • The top frame. Pick on the image refuses an element inside an iframe.
  • What a view shows. A test's own screencast, a heavy page, a popup, a download and a dialog: Watch a running test.
  • The middle button stays the window's. It would open a link in a tab the view does not show; Shift+click picks instead of clicking.
