Reuse forecast ​

The reuse forecast answers two questions from the coverage your runs already record: how much of the last month's test time re-ran code that had already passed unchanged, and which tests failed even though the code they ran had not changed. It lives on a project's Selections page and in the get_reuse_forecastMCP tool.

NeedsReporterCapture fixtures

What counts as reusable ​

The forecast reads the 30 days before the project's latest run. A result is reusable when an earlier result of the same test, in the same Playwright project, the same environment and another run, passed on its first attempt, is at most 14 days older, and either:

  • recorded file versions (runtime, path and git blob) that are all among the versions the result itself ran;
  • or ran at the same commit, both runs on CI, which also counts a failure that stopped before reaching code the pass ran.

For a deployed environment, both runs also ran the same version of the application (below); a run of one whose version nothing names is never reusable.

The code that pass ran had not changed, so a run could have skipped the result and kept the pass. The card gives the share of test time that was reusable, split between the default branch and the other branches when both have results: a branch's results may match a pass recorded on the default branch, since the comparison is by content, not by branch.

Failed with the code unchanged ​

A reusable result that failed, or passed only on a retry, ran code identical to an earlier pass. Its failure came from the test, its data or its environment, not from a change to the application. The card lists those tests, each with the failing execution and the pass it matched, which is strong evidence when you investigate a flaky test.

What it needs, and its limits ​

  • Coverage with file versions: code reach at coverage.browser: 'functions' or 'lines', or server coverage. With 'files' a test records which files it ran but not their version. A pass stands in for a later result only when it recorded file versions; a result that recorded none is reusable only at the same CI commit as such a pass.
  • An upper bound. The comparison sees the application files coverage records. A change to the test code itself, to the Playwright configuration or to a dependency is not part of it, and would make more tests run.
  • Runs that do not count: Flake Lab, probe, bisect, reproduction, piwi bug and private runs, and runs flagged as an environment incident.

Skipping reusable tests ​

Experimental. With the pass reuse capability on, piwi plan and piwi run --reuse skip the tests the forecast would count as reusable, with a stricter rule. A test's pass stands in for it only when that pass came from a clean checkout of a commit, with the same Playwright version and environment, and every result of the test in that run passed on its first attempt with coverage naming its file versions. The environment is the label the run reports (--environment, else PIWI_ENVIRONMENT; piwi run passes the flag to Playwright as the variable, which the reporter's environment option overrides when the config sets one), resolved as a run's label is; a run that names none reuses the passes of any environment. For a deployed environment, the pass ran against the application it runs now: the same commit, from its latest deploy marker or its servers' appCommit, else the same application versions its servers report. With neither, every test runs. Mark an environment whose application the config's webServer builds as built from the checkout: as a deployed one, its passes stand in only where a version is named. The working tree is diffed against that commit: the test runs when impact from that diff selects it, when a changed file maps to no test, or when a file the pass ran changed. A test that is quarantined, in an open failure cluster, failed or was retried in its last 20 executions, tagged @no-reuse, or in a spec file holding a serial group always runs. A run skips only the tests the plan names, in the Playwright projects their pass ran them in, so a new or renamed test runs. The diff counts untracked files, and a commit a shallow clone lacks is fetched. A plan is kept for 24 hours, and a job other than the one that made it uses it only when both checkouts are clean at the same commit; a job that cannot use it (an unreachable dashboard, an expired plan, another checkout) runs the whole suite, not a shard of it. The run records the tests it skipped and did not execute as its reused results: the run page's header counts them and lists them with the pass each one reuses, the pull-request comment counts them, and the get_run MCP tool returns their count. The run's own status, pass rate, flaky scores, durations and fix verification read executions only. The CI merge gate can limit reuse, and counts a reused test as passed in a run that passed with no run error. A run that claimed a plan it was not made for (another commit, a dirty checkout, another Playwright version or environment, another version of a deployed application, an expired plan) records no reuse, and fails the gate's reuse rules. A run whose shards' blob reports are merged by merge-reports claims no plan, so its reuse is not recorded.

Commands: plan. Design record: pass reuse.
