Write, run and fix a test ​

NeedsReporterCapture fixtures

This page takes a new test from an empty spec to a passing run, and names the tool for each step. Each step has a page of its own; this one is the map. The editor does most of it, in VS Code or a JetBrains IDE; Piwi Picker, the browser extension, does the same steps from the browser, and the desktop app runs them on your machine without an editor.

Before the first test ​

  • The capture fixtures in your specs: a test that imports test from @playwright/test runs, but never stops at a breakpoint, and the run says so (Capture fixtures).
  • The editor extension, connected to your instance or to the desktop app (Editor extensions, Editor connection).
  • Optional: Piwi Picker, paired with the editor, to pick and record in your everyday browser and follow runs in its Runs window.

Write it ​

Record a new test file offers the spec beside the one you are in, else in the config's testDir, and writes what you do in the browser as a test, with locators verified on the page and the page objects of your suite where they match. Record here writes steps at the cursor, in a test, a page object or a helper. A flow recorded in Piwi Picker lands at the cursor the same way through Send to editor: at the top level of a spec, as a new test.

Run and watch it ​

A run Piwi starts reports to the instance like any other, with the run's origin. In a project that runs in CI, a failure seen only in developers' own runs stays out of the team's inbox until someone shows it; one that fingerprints like a failure CI saw joins that cluster (Failure clusters & the inbox). A run you start in a terminal is followed too, when the editor is open: Runs started outside Piwi.

Stop it and write the fix there ​

Set a breakpoint on the line you are working on and run the test. It stops before that line's call, in a headed browser with Piwi's pause bar, or, headless, with the page shown in the editor. Pick a locator, Record here, Assert and Mock a request write their code where the stopped statement stands now, after the edits you made since the run started (Code from a pause); End the test skips the rest of it (End the test).

When it fails ​

In a run Piwi started, a failing test holds its page where someone can see it (a headed browser, or while the Runs window is open), and the editor shows the failure as a stop, with the same actions. Otherwise its page on the instance explains it: the clues rank the likely cause, and the Locator fix panel offers the replacement locator. Debug in my editor on that page runs the failing test again from the editor and stops at the line it failed on.
