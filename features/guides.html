Guides ​

NeedsReporter

A guide walks you through one task on your own dashboard: a popover on each part of the screens the task uses, in order, each with a link to the docs page that explains it. The guides are written in advance, so they need no AI model and work on every instance, the same way each time.

Opening a guide ​

Open the command palette (Ctrl + K, ⌘ + K on macOS) and pick a guide under Guides, or type the task: a guide is also found by words such as ollama, slack or selector. The assistant panel lists them too when its conversation is empty, and when no AI model is configured; starting one closes the panel.

Next and Back move between the stops, opening the page each one is on. × or Esc ends the guide, and so does going to another page yourself. While a stop shows, the part it points at cannot be clicked: a guide shows the dashboard and changes nothing.

Following the way ​

A guide takes the way you would take yourself, and shows it. Before it opens another page, a tab, a folded section or a menu, it points for a moment at the link or the button that does it, when that link is on the screen: an entry of the sidebar, a row of a list, a tab. The line at the top of each popover says where the stop is: the page's breadcrumb, then the tab and the section it sits in, the ones the guide just opened in color.

When a stop explains several parts of the screen, it numbers them: each number on the page matches one line of the popover, and pointing at a line enlarges its number on the page.

On your own data ​

A stop on the page of a project, a run, an execution, a failure cluster or a test opens one of yours, which the guide finds as it starts: the project updated last, the newest finished run, a failure of the newest failed run, the open cluster seen last, the flakiest test, or the first saved dashboard you can edit. When your instance holds none yet, such as no saved dashboard, the stop shows in the middle of the screen instead, with a line saying when that part of the page appears.

The guides walk the dashboard's own screens. For the work done elsewhere, in your Playwright project or your CI, a stop shows the screen with the command or the setting, and its docs link has the rest.

Suggested on a page ​

Three pages suggest a guide, or a question for the assistant, when what they show calls for one:

PageWhenOffers
SetupA capability is neither in use nor declinedAsk: which of them your runs would use, and what each one needs
A failure clusterIts diagnosis read no commits, and no SCM token is set for the project or the instanceShow me: Add the SCM token
An executionIt timed out, or its leading clue comes from the network, the server logs or the console, and the project has not decided on the capture fixturesShow me: Add the capture fixtures

A fixed rule over what the page already shows decides; no AI model is called. A page shows one suggestion at most, and a browser at most three a week. Don't show again hides one for good: the dismissal is kept on the server for your account, so it stays hidden in every browser, and with authentication off it is hidden for every visitor. A suggestion whose guide is not listed for you does not show. A question needs the assistant and an AI model to answer it, so declining the assistant or AI on the Setup page turns the Setup suggestion off; the two that offer a guide need no model and keep showing, and Don't show again still hides them.
