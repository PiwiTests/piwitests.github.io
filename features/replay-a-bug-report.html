Replay a bug report ​

NeedsBrowser extension

Replay plays a bug report's steps again in a tab, with a cursor that moves to each element and a caption saying what it does, then says whether the bug shows there. It suits the developer who receives the report: open the app on your own dev server, and the steps run there, with your session and your browser's developer tools at hand.

Choosing a report ​

  • From the finished report, Replay plays it at once on the same site. The review of a recording of actions has the same Replay, to check its steps before you export them.
  • From the popup, Replay a bug report (R) asks for the site's access if needed, then for the report: the .piwibug file (or the same file named .zip) or its steps.json, the text of a steps.json pasted in, the report or the recording of actions just made in this browser (Use the actions recorded in this browser), or, connected, one of the project's reports on Piwi.
  • From a failed execution on the dashboard, Export → Bug report (.piwibug) makes a report from the test run (below), and Steps (steps.json) copies its steps to paste.

The steps run on the tab's site, whichever site they were recorded on. A step that opens its page in a new tab, such as a link that opens an order beside the list, takes the replay to that tab, as the recording went on there.

The answer ​

Each element is looked for with every locator it was recorded with, the one the failing test uses first. When that one finds nothing for two seconds, finds several elements, or finds one the other locators disagree on, the element most of them agree on is used, and the step says which locator found it: a label that changed or an id made up on each load does not stop the replay. The element is then waited for as Playwright waits: visible, enabled and still, for as long as Playwright waits or, when you waited longer for it while recording (a reply that takes the server fifteen seconds), that long and a few seconds more, up to a minute. The replay ends with one of three answers:

  • Reproduced: an expected result does not hold, such as a total that still reads "Total: 50", and the panel says whether that is the value reported.
  • Not reproduced: every expected result holds here.
  • Could not reach the bug: a step could not be played (it found no element, several, or a disabled one, or the flow ended on another page) and you stopped there. The data, the login or a flag differ here.
  • Failed at step 4, as in the test run: in a report made from a test run, the step that could not be played is the one the test failed at.

Under the answer, the panel lists the failed requests and console errors the page showed during the replay, such as "POST /api/cart/coupon answered 500": from the moment the replay started, never those of the recording, even when you replay on the page you just recorded the report on. For a report from Piwi, Share result… records the answer on the report, with the site it ran on, after showing what it sends.

Step by step waits for Next before each step, with the element outlined, so you can set a breakpoint first.

When a step cannot be played ​

A step Replay cannot play is handed to you rather than ending the replay. The panel says why, names the step in words and, when the report has a screenshot of each step, shows the page as it began there, the element outlined. It lists the locators the element was recorded with and outlines on the page every element they still find, such as two buttons where the recording saw one, as the page changes. Do it yourself on the page, then choose:

  • I did it, continue: the replay goes on with the next step, even when your action loaded another page or opened one in a new tab.
  • Skip this step: it goes on without it.
  • Stop here: it ends there, and says it could not reach the bug.

A password, or a card number, its security code or a one-time code, is never in a report, nor what was typed when the sender left the typed values out: Replay hands that step to you to type it. A click or a key the page never got is handed to you too: a browser dialog in front of the tab, such as Chrome's warning about a password found in a data breach after a login, takes the input. Close it, then do the step. A hover recorded without any locator is skipped, since the next step points at its own element.

Under the answer, the panel lists the steps played by hand.

A report made from a test run ​

A .piwibug exported from a failed execution holds the test's steps up to the failure, setup hooks included, and its failing assertion with what it expected and what the run received. What the run did not keep enough of to play becomes a manual step, which Replay hands to you as above, with the line of the test it stands for: a click at a point of the page, a value the run kept only in part, a file choice, an option chosen by its index or several options chosen at once, a check with a regular expression. Replay writes it in Piwi Picker's language. API requests, scripts run in the page, route mocks and checks on values are not steps at all: the report's Markdown lists them under Not replayed, with why.

When the test failed on an action rather than on an assertion, the report says which step; reaching it and failing there answers Failed at step N, as in the test run, and playing it answers Not reproduced. A typed password is never in the report: the step asks for it.

A test run does not keep the page each step happened on once a click may have opened another, so Replay does not follow such a step into a new tab: it stays in the tab it started in, and a step the test played in a popup is handed to you.

Trusted input ​

In Chrome and Edge, Replay sends trusted input as Playwright does: a real hover, clicks, keys and drags that the page cannot tell from a person's. Chrome shows its debugging bar until the replay ends. In Firefox, when the browser refuses the session, once the bar is cancelled, or once the browser refuses one of its commands (the bar then closes), Replay goes on with the page's own events; the panel says which, step by step.

A report names the files a step chose but never carries them: Replay asks you to choose them, or to skip the step.

With trusted input, each step plays at the viewport size it was recorded at, in CSS pixels whatever your zoom, and the tab gets its own size back when the replay ends. Otherwise the panel says when the window's size differs from the recorded one, so you can resize it.

Running it with Playwright ​

Run with Playwright…, beside Start and on a finished replay, sends the steps to the paired desktop app, which runs them in your project once you confirm it there.

Limits ​

  • It plays one site, in the top-level document only, as the report was recorded. A step that opens another site, or an address that is not a web page, is handed to you.
  • Share result… and Run with Playwright… are the only parts that send anything, each after showing what it sends.
