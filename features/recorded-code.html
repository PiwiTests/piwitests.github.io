Recorded code ​

A recording from the editor, and a flow sent from Piwi Picker, are written as the code your suite would hold: locators verified on the page, calls to your own page objects and helpers, no password in the file. The Playwright config sets how that code looks for everyone who records in the repository.

What a recording writes ​

  • Locators come from the same converter as Piwi Picker's recordings and piwi codegen: each is verified to find the element alone on the page, the stable ones first and those your tests already use preferred. A check of the element's text takes a locator that does not find it by that text, when one is not brittle. A getByTestId uses the attribute your config sets.
  • Pages: an address on the project's baseURL is written as a path, and the step that leads to another page is followed by a wait for it, except next to a call to your own code, which waits for its pages itself.
  • Imports: a call to your own code, and expect when a step checks something, are imported at the top of the file when it lacks them: expect from @playwright/test, or from your fixtures module when the file or a spec beside it imports expect from there. A new test in a file that imports no test imports it as the specs beside it do. A spec that loads test with require gets require lines after its last one.
  • Titles: a new test is titled recorded flow, numbered (recorded flow 2) when the file has one already.
  • Your own code: when the editor is connected to an instance or the desktop app, steps that match one of your test functions become a call to it, as soon as the last of those steps is recorded.
  • Passwords are never recorded: the code reads them from an environment variable named after the field, such as process.env.E2E_PASSWORD, including in a call to a page object.

Code options in the Playwright config ​

How the recorded code looks is set for the whole repository in playwright.config.ts, under the '@piwi' key at the top level, next to testDir and use. Everyone who records in the repository from the editor gets the same code, with or without an instance; piwi codegen reads its own flags instead:

ts
import { defineConfig } from '@playwright/test';
import type {} from '@piwitests/reporter'; // declares '@piwi' on the config; already there with wrapConfig

export default defineConfig({
  testDir: './tests',
  '@piwi': {
    codegen: {
      testSteps: 'page',
      tags: ['@recorded'],
      annotations: [{ type: 'piwi:owner', description: '@shop-team' }],
    },
  },
});
OptionDefaultWhat it does
pageWaitstruefalse leaves out the wait for the next page after a step that leads to it
values'literal''env' reads every typed value from an environment variable named after its field, not only passwords
envPrefix'E2E_'What those variables start with, as in E2E_PASSWORD: upper-case letters, digits and underscores
testSteps'none''page' wraps the steps of each page in await test.step('/cart', …), so the report reads like the scenario; in a test only, not in a page object or a helper
tagsnoneTags a new test gets
annotationsnoneAnnotations a new test gets, { type, description? }

The editor reads the section through your project's own Playwright, so it applies to the recordings started after the config is saved, and to what Piwi Picker sends to the editor. An unknown option or a value of the wrong kind is left out, and the recording says so when it starts.
